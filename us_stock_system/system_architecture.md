# 美股分析系統 (US Stock Analysis System) - 架構規劃

> **架構設計理念**：採用微服務/領域驅動設計 (DDD) 的概念，將「UI展示」與「底層資料邏輯」切離，以確保系統具備高穩定效能與後續擴充性。

## 📌 暫緩處理與待辦清單 (Parked Items)
以下項目已記錄，將視開發進度於未來階段再行處理：
1. **Earning Call 逐字稿** (資料來源成本與 NLP 處理較為複雜)
2. **總經數據與資金面指標** (先專注微觀個股與個人部位紀錄，總經等後續補上)

---

## 🛠️ 技術選型 (Tech Stack Split)
為了發揮不同語言各自的最佳優勢，後端服務將嚴格對應底下的四大模組，拆分為 **Python** 與 **Java** 運作：

* **🐍 Python 負責部分 (資料與運算)**：
  * **1. 市場數據中心**：處理外部數據爬蟲、API 串接與大數據清洗。
  * **3. 量化與分析引擎**：利用豐富的資料科學套件，處理複雜的回測運算、估值計算與金融模型。

* **☕ Java 負責部分 (業務與排程)**：
  * **2. 用戶資產與財務模組**：提供高穩定、強型別環境，確保個人資金紀錄、出入金及稅務計算百分之百精準。
  * **4. 事件觸發與警報服務**：負責建立穩定的系統排程 (CRON) 機制及對前端推播。

---

## 🏗️ 系統底層架構 (Backend & Logic Layers)

### 1. 市場數據中心 (Market Data Layer) 🐍 [實作語言: Python]
**職責**：專門負責單向抓取、清洗與儲存外部公開市場唯讀數據（關聯資料庫），並具備本地/雲端「檔案系統 (File System / Object Storage)」來保存源文件。
* **各板塊的熱力圖報價** (Sector Heatmap)
* **重點個股財報數據** (Earnings Reports)
* **10-K 年度報告與原檔** (SEC Filings)：保留最原始的完整 PDF 或 HTML 檔案，不只存解析後的數字。
* **每日新聞追蹤** (Daily News)
* **內部人交易與機構持倉** (Insider Trading & 13F)

### 2. 用戶資產與財務模組 (Portfolio & Accounting Layer) ☕ [實作語言: Java]
**職責**：處理具高度隱私與需要精準計算的敏感私人財務紀錄。
* **記錄個人部位** (Positions)
* **出入金紀錄追蹤** (必須包含**匯率轉換**與 30% 股息預扣稅等**稅務影響**的嚴謹計算)

### 3. 量化與分析引擎 (Quant & Analytics Engine) 🐍 [實作語言: Python]
**職責**：專職執行複雜數學運算與回測，與一般 I/O 操作分離以確保效能。
* **回測系統架構** (需處理歷史股價與除權息/股票分割)
* **估值儀表板** (本益比河流圖 P/E Bands、股價營收比 P/S 等進階視覺化指標)
* **被動投資績效對比** (與 VOO / QQQ 定期定額回測比較，買入時間點可動態調配)

### 4. 事件觸發與警報服務 (Event & Notification Service) ☕ [實作語言: Java]
**職責**：常駐於背景執行的監控機制 (CRON, Workers)，發出非同步通知。
* **警報與通知系統** (包含股價漲跌觸發、重點新聞推播、財報日期與除權息日提醒等)

---

## 🖥️ 前端展示介面 (Frontend UI Modules)
對應用戶直覺操作，畫面上主要劃分為三個視覺區塊：
1. **市場觀察儀表板 (Market View)**：對接 `數據中心` 與 `警報服務`，展示大盤熱力圖、公司基本面與通知設定。
2. **估值與分析區 (Analytics View)**：對接 `量化與分析引擎`，顯示各式估值圖表與回測報告。
3. **投資組合管理區 (Portfolio View)**：對接 `財務模組`，提供使用者新增部位、紀錄出入金與查看總資產淨值。


# 技術選型確認 (Technical Stack Choices)

## 1. Python 端 (負責模組 1 與模組 3：資料爬蟲與量化回測)
*   **Web 框架**：FastAPI 
    *   **優勢**：支援非同步 (Async)，效能極快，且會自動產生清晰的 API 文件 (Swagger) 方便與 Java 端或前端進行介接。
*   **套件管理**：Poetry
    *   **優勢**：當前 Python 現代主流的依賴與套件管理工具。

## 2. Java 端 (負責模組 2 與模組 4：資產計算與排程警報)
*   **核心框架與版本**：Spring Boot 3 + Java 21 🏆
    *   **優勢**：現代微服務的業界標準，可直接享受 Java 21 「虛擬執行緒 (Virtual Threads)」帶來的強大併發處理效能紅利。
*   **建置工具 (Build Tool)**：Gradle
    *   **優勢**：相比 Maven 寫法更為靈活，且建置速度更快。
*   **資料持久化 (ORM)**：JDBC + SQL
    *   **優勢**：輕量化原生操作，讓開發者對 SQL 具備最高控制權，避免 JPA 的複雜性與不可預期效能。

## 3. 共用基礎設施 (跨語言溝通與儲存)
*   **主資料庫 (Database)**：PostgreSQL
    *   **優勢**：在處理高精度金額 (Decimal)、複雜查詢與時間序列資料上，穩定度與原生支援皆佔據極佳優勢。
*   **Python 與 Java 如何溝通？**
    *   **機制**：Message Queue (如 RabbitMQ 或 Redis)
    *   **應用場景**：當 Python 爬完最新報價後，可利用 MQ 丟訊息給 Java 端去異步觸發警報機制。這種設計雖然較複雜，但非常適合後期系統漸趨龐大時的「解耦合」，確保系統高可用性。
